# CSRF

## What is CSRF?

Cross-Site Request Forgery occurs when an attacker tricks an authenticated user's browser into sending an unwanted request to a trusted application.

## Attack Flow

```text
Victim logged in
      ↓
Attacker-controlled page
      ↓
Browser sends request
      ↓
Session cookie included
      ↓
Server accepts request
```

## Root Cause

The server verifies authentication but does not verify that the request was intentionally generated by the application.

## Example

```http
POST /api/change-email
```

The attacker causes the victim's browser to submit this request while the victim is logged in.

## Defense

Use CSRF tokens:

```text
Request
  ↓
CSRF Token
  ↓
Server validates token
  ↓
Allow / Deny
```

Also use appropriate cookie protections such as `SameSite`.

## Testing

```text
Normal request + valid CSRF token → 200
Missing CSRF token              → 403
Invalid CSRF token              → 403
```

## XSS vs CSRF

XSS → execute attacker-controlled code in the victim's browser.

CSRF → cause the victim's browser to perform an unwanted action.

## Key Principle

> Authentication proves who the user is; CSRF protection helps verify that the request was intentionally generated by the application.
